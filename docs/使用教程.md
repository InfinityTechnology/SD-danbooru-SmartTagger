## 1. 安装与首次启动

### 方式一：运行打包好的 exe（推荐）

1. 到 Releases 下载 `SmartTagger-v1.0-win64.zip`
2. 解压到任意目录（**路径里最好不要有中文**）
3. 双击 `SmartTagger.exe`

> 首次启动需要解压临时文件，等待 5–10 秒属正常现象。程序是**单文件绿色软件**，不写注册表，删除文件夹即卸载。

### 方式二：源码运行

```bash
git clone https://github.com/<your-name>/SmartTagger.git
cd SmartTagger
pip install -r requirements.txt
python main.py
```

Python ≥ 3.10。Windows 用 `onnxruntime-directml`（N 卡 / A 卡 / Intel 通吃），Linux / macOS 用 `onnxruntime`。

## 3. 第一步：环境与依赖

打开软件默认停在这一页，程序已自动完成一次检测。

### 读懂检测表

| 检测项 | 含义 |
|---|---|
| 操作系统 / Python | 基础运行环境 |
| GPU | 当前识别到的显卡（核显也能用） |
| onnxruntime | 推理运行时，必装 |
| onnxruntime-directml | Windows 统一 GPU 后端，NVIDIA / AMD / Intel 都走它 |
| PySide6 / huggingface_hub | 界面与模型下载依赖 |
| 推理后端 | `DmlExecutionProvider` = GPU 加速已启用 |
| WD14 模型 | 打标引擎本体（约 400MB） |

### 三件事

1. **缺依赖** → 点「一键安装缺失依赖」。默认装进当前 Python 环境；想装到别处（比如便携目录），先在输入框填安装位置再点安装。
2. **模型未下载** → 在「WD14 模型缓存」卡片确认目录，点「下载模型」。首次约 400MB，之后**完全离线**。
3. **装完记得点「刷新检测」**，状态胶囊变绿即可进入下一步。

> exe 版自带 `models/` 目录的话，打开即为「已缓存」，无需下载。

## 4. 第二步：数据集打标

### 4.1 选择目录

- **目标文件夹**：图片所在目录（png / jpg / jpeg / webp / bmp，当前处理一层目录，不递归子目录）
- **导出文件夹**：留空 = txt 直接写在图片旁边；填写 = 标签统一输出到别处

选定目录后：

- 「文件预览」卡片出现**缩略图网格**，**绿色角标 = 已有标签文件**
- 下方统计行显示 `N 张图片 · M 个标签文件 · K 待打标`
- 若检测到已有标签文件，会弹窗询问：**「Yes」= 跳过已打标的图片**（推荐，配合增补数据集）；「No」= 忽略提示，稍后手动取消勾选「跳过已打标」即可全覆盖

### 4.2 填参数

| 参数 | 怎么填 |
|---|---|
| **触发词** | 你的 LoRA 专属召唤词，会写在每条 caption 最前面。建议加数字避免和底模已有概念冲突，如 `wodelora1919810` |
| **固定前缀** | 每张图都成立的通用标签，逗号分隔，如 `1boy, solo`。**注意**：写进前缀的标签会被触发词吸收，不要把角色特征写进来 |
| **通用阈值 0.35** | 越低标签越多越杂，越高越精简。服装/动作缺失就调低，标签太脏就调高 |
| **角色阈值 0.85** | 防止把你的角色误判成别的角色名写进标里，一般不动 |
| **低频阈值 500** | Danbooru 上出现次数低于此值的标签会被丢弃（底模大概率不认识它们） |
| **通配删背景** | 勾选后所有 `*background` 标签全部删除，防止触发词把背景一起学进去 |
| **跳过已打标** | 勾选 = 只处理没有 txt 的图片 |

### 4.3 开始打标

点「开始打标」，进度条实时走，日志区滚动输出每张图的识别结果。完成后日志显示 `[DONE] 完成 N 张，用时 Xs`，预览区角标同步刷新。

**打完先抽查 10–20 张**：对照图片读 txt，确认角色特征（发色 / 瞳色 / 服装 / 标志性物件）都在。不满意的参数改完重跑即可——记得取消勾选「跳过已打标」。

### 4.4 输出格式

```
wodelora1919810, 1girl, solo, black hair, long hair, green eyes, school uniform, standing, outdoors
```

- 全小写、空格代下划线（Anima 底模规范），仅 `score_*` 类保留——而它们默认已被过滤
- 顺序：触发词 → 固定前缀 → WD14 识别标签

## 5. 第三步：数据集清洗

清洗是**纯文本算法**，秒级完成，不跑推理、不占显存。它读取每个 txt，按规则删除标签后写回。

1. 选目标文件夹（导出留空 = 原地覆盖）
2. 勾选过滤规则（默认全按社区共识预置）：

| 规则 | 作用 |
|---|---|
| 通配删除 `*background` | 背景类标签全部移除 |
| 删除 rating | general / sensitive / explicit 等分级标签 |
| 删除画师标签 | 防画风污染 |
| 删除版权 / 作品标签 | 防作品概念污染 |
| 删除 WD14 判出的角色名 | 防误判污染（你的角色应该是触发词，不是别人的名字） |
| 删除 meta 类标签 | monochrome、comic 等（可选） |
| 删除源噪声与质量分数标签 | 内置黑名单：watermark、lowres、masterpiece、score_1~10… |
| 删除低频长尾标签 | 阈值默认 500，与打标页共用 |

3. 点「开始清洗」。若**图片数 ≠ 标签文件数**（或有文件名未成对），会先弹窗确认——点「Cancel」不做任何改动，先去检查数据集。

> **白名单保护**：角色核心特征（1girl、发色、瞳色、兽耳、机械肢体等）在任何规则下都不会被误删。自定义角色请编辑 `core/filters.py` 的 `WHITELIST`。

## 6. API 接入（可选）

本地引擎已覆盖绝大多数场景且**零成本**，只有当你需要视觉语言模型（VLM）写细粒度描述（比如复杂互动、构图叙述）时才用得上云端 API。

- 填 API 地址（兼容 OpenAI Chat Completions 格式，如中转站 / `https://api.openai.com/v1`）、API Key、模型名（如 `qwen-vl-max`）
- 点「测试连接」验证连通性
- **不填 Key = 功能完全关闭，不产生任何调用**；Key 仅保存在本机

## 7. 参数详解

### 阈值怎么调

| 现象 | 处理 |
|---|---|
| 服装 / 动作标签缺失 | 通用阈值 ↓（0.35 → 0.25） |
| 标签太杂、噪声多 | 通用阈值 ↑（0.35 → 0.45） |
| caption 里出现别的角色名 | 角色阈值 ↑，或确认「删除角色名」规则开启 |
| 标签里全是生僻词 | 低频阈值 ↑（500 → 800） |

### 打标 or 清洗，用哪个？

- **还没打标** → 直接用打标页，打标时过滤规则已生效，一步到位
- **已有 txt（手工精修过）** → 用清洗页。它只删不改不新增，不会碰你手工调整过的内容

## 8. 常见问题

**Q：核显能跑吗？**
能。DirectML 走 DX12，Intel / AMD 核显都支持，只是速度慢于独显，大批量建议夜间挂机。

**Q：为什么标签是空格不是下划线？**
Anima 等底模官方规范：标签小写、空格代下划线，只有 `score_*` 保留下划线。

**Q：已有 600 张手工精修的标，会被覆盖吗？**
不会。保持「跳过已打标」勾选即可，程序只处理没有 txt 的图片；清洗页对已有 txt 只删不改。

**Q：黑白双形态的角色（如不同发色形态）怎么办？**
WD14 会分别打出 `black hair` / `white hair`，两种形态的图各自带各自的特征标签即可，**不需要**拆数据集。

**Q：支持子目录吗？**
当前版本处理目标目录下一层的图片，不递归。需要的话先把图集中到一个目录。

**Q：设置（语言 / 主题 / 路径）存在哪？**
Windows 注册表 `HKEY_CURRENT_USER\Software\SmartTagger`，删除即重置。

**Q：能带上我自己的黑名单吗？**
编辑 `core/filters.py` 的 `DENY_EXACT`（源码运行），或打包前修改后重新打包。
